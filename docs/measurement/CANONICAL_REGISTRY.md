# Canonical N1 registry and artifact guide

[`measurement/metric_registry.py`](../../src/latency_fingerprinting/measurement/metric_registry.py)
declares all 31 reviewed outputs in source: 15 gauges and eight separate
rate/total pairs. It does not load definitions from the P0 adapter, normalization
configuration, Markdown inventory or runtime plugins. The canonical registry is
immutable and contains fixed metadata:

- Registry version: `latency-metrics-v2.0.0`.
- Definition semantic versions: `1.0.0`.
- Registry release timestamp: `2026-10-06T00:00:00Z`.
- Registry schema version: `metric-registry-v1`.

`build_metric_registry()` deterministically builds the same registry from those
declarations. `CANONICAL_METRIC_REGISTRY` is the frozen instance.
`get_metric_definition(name)` resolves only registered names, rejecting unknown
and old P0 delta names. `render_metric_registry()` emits sorted, indented,
newline-terminated JSON with camelCase aliases. No call reads the current clock.

The checked-in artifacts are
[`metric-registry-v1.json`](../../schemas/metric-registry-v1.json) and
[`metric-registry-v1.schema.json`](../../schemas/metric-registry-v1.schema.json).
The schema uses the strict models described in
[`REGISTRY_MODELS.md`](REGISTRY_MODELS.md); cross-field invariants still require
model validation. Neither artifact is an observation or matcher input.

## Export and inspection

```bash
.venv/bin/python -m latency_fingerprinting export-metric-registry \
  --output schemas/metric-registry-v1.json
.venv/bin/python -m latency_fingerprinting export-metric-registry \
  --output schemas/metric-registry-v1.json --check
.venv/bin/python -m latency_fingerprinting export-schemas --output schemas --check
.venv/bin/python -m latency_fingerprinting validate schemas/metric-registry-v1.json
```

Registry export reuses the schema exporter's sibling temporary-file writer and
atomic replacement. Existing file permissions are preserved; replacement failure
leaves the previous artifact intact and cleans up the temporary file. The output
parent directory is created only on write. CLI failures return nonzero with an
error message rather than a traceback.

`--check` compares exact UTF-8 bytes and does not write, change modification time
or create directories. It reports missing files, byte-order marks, CRLF conversion,
invalid UTF-8 and content changes as drift. Wrong-sized artifacts are rejected
without reading their contents; other reads are bounded by canonical length plus
one byte. `validate` uses the existing bounded, duplicate-key-safe file reader.

`export-schemas` now includes the additive registry schema with the three frozen
P0 schemas. A test compares the registry artifact to generated bytes and validates
it through both `MetricRegistry` and a Draft 2020-12 JSON Schema validator with
format checks. `jsonschema` is a development-only dependency; runtime dependencies
remain unchanged.

## Meaning changes and drift

The registry and schema checks are part of CI, including the existing Python 3.11
and 3.13 test suites. The release pin in
[`test_metric_registry.py`](../../tests/measurement/test_metric_registry.py) freezes
the `v2.0.0` artifact's SHA-256:
`50329d193303c271194b28e9164ae8627dd257d7620174c5ab136ba209864884`.
Regenerating an artifact after a source edit cannot silently change that release.
Changing meaning requires explicit definition/registry version review and updating
the release expectations; differences fail the checked-in artifact and release-pin
tests until the deliberate update is made.

The same test module compares each definition's source, field, kind, units,
aggregation, clock, cadence and missing/reset policy with
[`METRIC_SEMANTICS_V2.md`](METRIC_SEMANTICS_V2.md). This inventory remains the naming
and semantics review surface; source declarations are the executable registry.
Settings such as target FPS remain context. Existing `P0_FEATURE_CONFIG` continues
to drive the production v1 analytical path.

The next step extracts immutable timestamped samples through the existing bounded
bundle reader. Gauge and counter aggregation, shadow reports, and observation-v2
adoption are not implemented by the registry export commands.
