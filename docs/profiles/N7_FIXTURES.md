# Profile fixture release

[`fixtures/profiles-v1`](../../fixtures/profiles-v1) freezes N7 software behavior
under fixture release `1.0.0`. Its 23 operand files and 34 cases are separate from
the `n7-profile-statistics-v1` method release. The
[release inventory](../../fixtures/profiles-v1/release.json) pins each operand,
the N6 dependency release and expected results; the checker pins the release
file itself. Existing N6 files are reused through that explicit dependency,
without copying or relabelling them.

```sh
python -m tests.profiles.check_reproduction
python -m pytest tests/profiles
python -m tests.packaging.check_wheel
```

The read-only checker validates the exact bounded inventory and SHA-256 pins
before execution. It compares API/CLI results with frozen independent snapshots
or linked-build projections, verifies the N6 source report against N6's independent
expectations, then checks both inventories and pins again. It also checks fixed
errors, silent successful writes, canonical output and preservation of existing
output on failure. There is no update/bless mode. Success prints one JSON receipt.

The installed-wheel check copies both corpora into temporary directories and
runs all 34 N7 cases against the installed console entry point outside the
checkout. Both CI Python jobs run reproduction and installed-wheel verification.

| Cases | Expected behavior |
| --- | --- |
| Policy and draft | Exact approved policy, canonical empty create result and standalone dispatch |
| Supported and group votes | Five training groups with votes 0–4 give center 2 and raw MAD 1; repeating windows in one group does not add independent votes |
| Availability 4/5 and 3/5 | Missing values remain null; four contributing groups still fail the five-group support gate, while three also fail availability |
| Coverage 17 and 16 | Five constant features leave 17 active and provisional support; six leave 16 and rejected support |
| Zero dispersion and four groups | Constant features and inadequate group support cannot create active weights or supported candidates |
| Lifecycle | Stale, rejected, superseded and rejected-draft revisions preserve parent evidence and bind exact reviews/replacements |
| Invalid revisions | Wrong review subject, terminal parent, rehashed false center, held-out feature values and a forged trusted state fail |
| Fourteen linked N6 cases | Twelve valid synthetic datasets remain rejected with zero selected values; wrong source binding and split leakage fail linked inspection |

The full arithmetic/lifecycle expectations come from the independent examples
and Decimal oracle established before production statistics/lifecycle code.
Linked exclusion expectations are authored from the frozen N6 entry decisions,
roles and partition membership. They are not snapshots generated by N7's builder.
Runtime reconstruction checks every retained group, feature, count and identity;
the earlier [design vectors](N7_DESIGN_VECTORS.json) additionally cover extreme
binary64 arithmetic and exact threshold boundaries.

**Provenance is `synthetic_and_model_only`.** Eligible report metadata in the
arithmetic/lifecycle snapshots is artificial and has no inspected acquisition
behind it. These declarations exercise standalone validation and administrative
operations, not a successful real linked build. Every valid linked dataset is
still excluded synthetic evidence. Review receipts are unauthenticated. Neither
corpus establishes real sample adequacy, diagnostic accuracy, physical acquisition
independence or trust promotion; no producer integration is run.

To change the release, review operand bytes and independent expected outcomes,
version the fixture release as appropriate, then explicitly update operand and
release pins. Do not regenerate expected results from current production output
to make a failing check pass.
