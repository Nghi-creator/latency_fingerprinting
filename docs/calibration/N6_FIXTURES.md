# Calibration fixture release

The synthetic corpus in [`fixtures/calibration-v1`](../../fixtures/calibration-v1)
freezes N6 software behavior separately from the evidence method release.
Fixture release `1.0.0` has 14 dataset directories and 35 input files. The
[`release.json`](../../fixtures/calibration-v1/release.json) inventory pins every
input SHA-256 and records independently authored expected entry decisions,
source-group/role counts, duplicate representatives and partition membership.
The reproduction checker pins the release file itself.

Run from an installed development checkout:

```sh
python -m tests.calibration.check_reproduction
python -m pytest tests/calibration
python -m tests.packaging.check_wheel
```

The checker is read-only and has no update/bless mode. It checks the exact
inventory and pins before inspection, compares all expected decisions/counts,
checks API/CLI canonical output parity and verifies the inventory again. It also
checks fixed private errors and preserved output for invalid inputs. Success
prints one JSON receipt with fixture release, case count and synthetic provenance.
The installed-wheel check copies this same corpus into a temporary directory and
runs every case against the installed console entry point outside the checkout.
CI runs reproduction in both supported Python jobs.

| Cases | Frozen behavior |
| --- | --- |
| `reviewed-response`, `reviewed-roles` | Otherwise supported synthetic evidence remains excluded; complete source groups retain training/validation/final-test assignments |
| `baseline`, `controlled-healthy` | Healthy N6 binding maps to N2 baseline; baseline and response inputs remain separate |
| `declared`, `missing`, `confounded` | Unverified, absent and confounded evidence remains visible with exact reasons and denominators |
| `duplicate`, `mixed-settings` | Re-encoded response aliases count once; different effective settings form separate partitions without creating independent source groups |
| `controlled-host`, `failed-effect`, `controlled-pacing` | Both N5 releases recompute their effects; failed effects remain excluded rather than being dropped |
| `split-leakage`, `wrong-binding` | Intrinsically formed declarations fail linked inspection when a component is divided or the actual source run disagrees |

Input arithmetic comes from synthetic N2/N3 test series and frozen synthetic N5
bundles. The retained outcome/reason/group/count expectations were specified
without calling the inspector. No report generated by the inspector serves as
the expected-decision oracle. Existing N2/N3/N5 source contracts and release pins
retain their meanings.

Every measured input is explicitly synthetic. All valid measured entries retain
`synthetic_only`; none qualifies real calibration. Review declarations and the
prospective split exercise software paths, not authenticated acquisitions or
historical timing. The corpus demonstrates no real sample adequacy, diagnosis
accuracy or producer integration. Real-provenance branches in unit tests are
artificial contract tests and are not published as real measurements here.

To change a release, explicitly review the input bytes and independent expected
outcomes, version the fixture release as appropriate, then update the input pins
and checker release pin. Do not regenerate expected outcomes from current
production output to make a failing check pass. Negative cases intentionally
fail linked inspection; their exclusion from the valid-result set is itself
part of the frozen expectation.
